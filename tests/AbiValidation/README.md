# VLC ABI validation

`vlclr_abi.g.c` is a compile-only probe generated by `tools/VLCLR.CImport`
(`emit`) from the pinned VLC headers. It checks the sizes, field offsets and
constant values of the generated interop structs in `src/VLCLR/Native/Interop`
against what a C compiler computes from the VLC headers. Any difference fails
at compile time through a `_Static_assert`. Do not edit it by hand; regenerate
it with the emit command (see `tools/VLCLR.CImport`).

The probe is C11, not C++: VLC's headers declare some types differently for
C++ (`vlc_threads.h`), and C++ scopes the records declared inside another
record. Symbols of one platform only are checked under `#ifdef _WIN32` or
`#ifndef _WIN32`.

Fetch the pinned headers first, then compile the probe against them:

```powershell
tools\VLCLR.CImport\fetch-headers.ps1
tests\AbiValidation\verify-vlc-abi.cmd artifacts\vlc-headers\include   # MSVC
```

```bash
tools/VLCLR.CImport/fetch-headers.sh
tests/AbiValidation/verify-vlc-abi.sh artifacts/vlc-headers/include    # GCC or Clang
CC=x86_64-w64-mingw32-clang tests/AbiValidation/verify-vlc-abi.sh artifacts/vlc-headers/include  # llvm-mingw
```

On Windows, llvm-mingw is the reference: VLC's Windows builds use it, and the
generated windows layouts come from its headers. MSVC is not a VLC compiler
and cannot parse every header (POSIX ones, GCC attributes): the probe leaves
those out under `_MSC_VER` (`output.probeMsvcExcludeHeaders` in the manifest),
along with the system headers' own types, which are mingw-w64's.

CI (cross-platform.yml) runs the probe on Linux, both macOS flavours and
Windows (MSVC and llvm-mingw) against the pinned headers, and also against the
headers of the latest VLC nightly. A failure against the nightly is a real
drift signal: VLC changed a layout since the pinned commit.
